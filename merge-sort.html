CLRS uses merge sort (chapter 2.3) to introduce divide and conquer. The idea has three parts: divide the problem into smaller copies of itself, conquer them by solving each one recursively, and combine the answers.

For sorting, that means splitting the array into two halves, sorting each half recursively, and merging the two sorted halves into one. The recursion stops at pieces of length 1, since a single element is already sorted.

All the real work happens in the merge. Picture two sorted piles of cards. Look at the top card of each pile, take the smaller one, and repeat until both piles are empty. Each element is taken once, so merging n elements costs time proportional to n.

Splitting in half gives about log n levels of recursion, and every level merges n elements in total. That is why the recurrence T(n) = 2T(n/2) + cn solves to O(n log n), in the best, average and worst case alike. The price is O(n) extra memory for the merge. Taking from the left half on ties keeps equal elements in order, so the sort is stable. 

merge_sort(A, lo, hi):
    if lo >= hi: return
    mid = (lo + hi) // 2
    merge_sort(A, lo, mid)
    merge_sort(A, mid + 1, hi)
    merge(A, lo, mid, hi)

merge(A, lo, mid, hi):
    L = copy of A[lo..mid]
    R = copy of A[mid+1..hi]
    i = 0; j = 0; k = lo
    while i < len(L) and j < len(R):
        if L[i] <= R[j]: A[k] = L[i]; i = i + 1
        else:            A[k] = R[j]; j = j + 1
        k = k + 1
    copy whatever is left of L, then of R, into A[k..]
